# 剧本：老项目摸底与设计溯源 (`understand`)

适用场景：接手陌生老项目、动手改复杂模块前、排查“怎么跑 / 为啥这样写”。**全程严格只读，不修改业务源码。**

## 执行步骤
1. **How — 查现状运行流**：
   - 小范围主厨直接定位，跨模块派只读 `scout`；
   - 厘清核心入口、数据流向、模块公开接口契约与测试入口；
   - 每条结论必须附精确文件路径与行号，绝不凭印象概括。
2. **Why — 查历史演进（Git 溯源）**：
   - 对反直觉或复杂逻辑用 `git log -S <关键词>`、`git log -L <起始>,<结束>:<文件>`、`git show <sha>` 追溯引入原因；
   - 明确区分**原始提交记录**与**当前代码推断**；若仓库无历史记录，直说“未查到原因”，绝不编造理由。
3. **懒沉淀 — 绝不抄写过时目录地图**：
   - **禁止**把目录树或 `package.json` 已有命令抄成大百科文档（代码自身就是真相）；
   - 仅当发现**只看源码绝对查不到的硬约束**（隐形禁区、业务黑话歧义、难逆转权衡）时，才按需在项目根目录极薄 `AGENTS.md`（≤60 行）或 `GLOSSARY.md`（纯术语定义，无实现细节）追加 1–3 条。
4. **交付结构**：一句话运行主线 + 关键文件与行号图谱 + 历史动机与风险禁区。
