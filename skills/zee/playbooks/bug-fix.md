# 剧本：Bug 定位与修复 (`bug-fix`)

适用场景：回归故障、运行报错、构建失败、语法损毁或边界逻辑异常。

## 执行步骤
1. **先抓现象，二分取证，无复现不写猜测补丁**：
   - 收集完整报错栈、失败命令与真实文件行段，优先用二分法（缩小输入/调用链/提交范围）排除假设；
   - **禁止保留“也许有用”的猜测性兜底代码（Belt-and-suspenders）**：被推翻的假设改动必须立即回滚，绝不带入正式修复。
2. **红灯先行（务实 TDD）**：
   - 优先编写最小单测复现并**亲眼看到失败（Red）**再改实现；
   - 若完整单测搭建成本过高或需重度 Mock 反而失真，改用最小确定性复现脚本/命令锁定真实红灯，同样满足红灯先行。
3. **精准读取与快速校验（防破坏现场）**：
   - 同一 `edit` 失败 1 次，必须先 `read` 该行段核对最新内容再重写，禁止盲目重试；
   - 每次改码立刻跑语法检查（如 `node --check <file>`）和窄单测，绝不留语法破损进入下一轮。
4. **最小根因修补（Green）**：针对根因做最小改动，严禁 `@ts-ignore` / 空 `try-catch` 吞错掩盖。
5. **全链路回归与先落袋收口**：复现转绿 + 跑通全量测试与 `.agents/verify-ctl.mjs`，再跑 `gate-tamper-diff --working-tree` 收口；**主测跑绿后必须先 `update-state`、`log-decision` 与 `git commit` 落袋**，禁止未提交前先折腾重型浏览器工具。
