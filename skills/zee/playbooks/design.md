# 剧本：修改设计 — UI/交互改版与架构重设计 (`design`)

适用场景：视觉风格改版、页面布局/动效/交互重构、高保真重构迁移、核心模块架构重设计。默认**零干扰自动驾驶**直通验收。

## 1. 先定基线与改版边界（禁止盲改）
- 运行 `<ZEE_TOOL> doctor --repo <repoRoot>` 拿到 `projectProfile` 并建总线 `init-run`；
- 明确本次属于哪一类（可同时命中）：
  - **重构保真型**（拆解/重写/打包迁移，未要求改风格）：1:1 锁定原有布局、配色与交互契约，零擅自改外观；
  - **主动视觉/交互改版型**：按目标风格完整重设计，先列出受影响页面/路由/核心交互状态表写入 `<busDir>/plan.md`；
  - **架构重设计型**：先跑通并按需补齐**外部行为特征测试（Characterization Tests）**锁死公开契约，再改内部结构。

## 2. 分支执行闭环
- **分支 A · UI 与交互改版**：
  1. 跨页面改动按路由/组件域拆分，单页小改直做，多页并行派发 `ui` 角色；
  2. 强制内置质量底线：桌面端 + 移动端双视口无溢出/无白屏、空态/加载态/错态/长文本极值态完整、按钮交互反馈明确无死按钮、高开销特效（如 WebGL/重动画）保留首屏性能与轻量降级方案；
  3. **消灭 UI 肉身代理**：主测/构建通过后，必须启动真实页面或无头浏览器/DOM 运行器核验核心视图渲染、桌面+移动视口、0 个未捕获 JS Console Error，并执行有限步探索式 `--fuzz`（连续点击、空输入、超长输入、窄屏切换）。
- **分支 B · 架构 / 模块重设计**：
  1. 由 `architect`（或主厨）对比 **2 种设计形态**（状态唯一 Owner、类型/目录环境约束收窄、调用方心智负担最小），将取舍记入 `decisions.tsv`；
  2. 渐进小步迁移，每一步保持特征测试与类型/构建全绿，最后清理旧路径死代码。

## 3. 防篡改、对抗审查与收口
- 运行全量测试、`.agents/verify-ctl.mjs`（若无且属 Web/应用型项目按 `verify.md` 自举）及 `<ZEE_TOOL> gate-tamper-diff --repo <repoRoot> --working-tree`；
- 架构重设计或核心界面改版派跨家族 `reviewer`（传 `--author-family <fam>`）核验爆炸半径与“使其安全的唯一关键事实”；非阻断坏味道写入 `finding add`；确认无误后落袋交付（附视觉/渲染实测证据与产物路径）。
