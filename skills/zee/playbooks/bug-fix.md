# 剧本：Bug 定位、聚类与根因修复 (`bug-fix`)

适用场景：回归故障、运行报错、构建失败、并发偶发异常、一次性涌入多条报错/告警。

## 执行步骤
1. **召回历史与幕僚长聚类（See the Forest）**：
   - 运行 `<ZEE_TOOL> recall --repo <repoRoot> [--topic <模块/报错词>]`（或 `list-runs <repoRoot> --decisions --limit 20`）核查过往已被证伪的假设、同类园艺簇与 ADR，杜绝新会话重踩旧坑；
   - 若一次性收到 **≥2 条报错/反馈**，先验证在当前 `main` 是否真实可复现（过滤过期/本地环境误报），将同根因、同模块的报告聚合成少数高杠杆修复主题，不盲目拆单重复修补。
2. **先抓现象，二分取证，无复现不写猜测补丁**：
   - 收集完整报错栈、失败命令与真实文件行段，用二分法（缩小输入/调用链/提交范围）锁定根因；
   - **禁止保留猜测性兜底代码（Belt-and-suspenders）**：被推翻的假设改动必须立即回滚，绝不带入正式修复。
3. **红灯先行（务实 TDD + 并发偶发连跑）**：
   - 优先编写最小单测复现并**亲眼看到失败（Red）**再改实现；若完整单测需重度 Mock 失真，用最小确定性复现脚本锁定真实红灯；
   - **并发/竞态/偶发 Bug**：必须连续运行复现命令 `5–10` 次锁定复现率，修完后再连跑 `≥10` 次确认 0 失败。
4. **精准修补与两败停损转轨**：
   - 同一 `edit` 失败 1 次先 `read` 最新行段再重写；每次改码立刻跑语法检查与窄单测；严禁 `@ts-ignore` / 空 `try-catch` 吞错；
   - **两败停损转轨（主厨 + 子代理联动）**：同一故障连续 2 次尝试未转绿，立即停止打补丁 → 将已排除假设写入 `decisions.tsv` → 切入 `understand.md` 做 `git log -S/-L` 溯源并**否定原前提假设**重开排查（多模型宿主可切换备胎模型）。
5. **全链路回归与收口**：
   - 复现转绿 + 跑通项目测试套件与 `.agents/verify-ctl.mjs`（若缺失则以项目原生测试兜底）；
   - 跑 `<ZEE_TOOL> gate-tamper-diff --repo <repoRoot> --working-tree`（纯新增回归测试归 `testFilesAdded` 不误报）；若发现缺失 Test Seam 或系统性脆弱点，用 `finding add` 入园艺队列；允许提交上下文下先 `update-state`、`log-decision` 与 `git commit` 落袋。
