# 剧本：性能分析、实证核查与单变量爬坡 (`perf`)

适用场景：启动慢、响应卡顿、包体过大、吞吐瓶颈或无人值守指标持续优化（`hillclimb`）。

## 执行步骤
1. **冻结基准与 5 项实证核查（吸收 `benchmark-checklist`）**：
   - 没有可重复数字前禁止优化；若项目无现成基准，先在 `<busDir>/artifacts/` 建立隔离、可重复执行的基准脚本并登记目标退出谓词：
     ```bash
     <ZEE_TOOL> update-state <busDir> --predicate "<客观目标表达式，如 p50<50ms 且单测全绿>"
     ```
   - 基准脚本须过 5 验：
     1. **明确瓶颈 Limiter**：用 profiler / 火焰图 / 耗时分段定位真正主瓶颈（并估算 Amdahl / 物理极限）；
     2. **配置对齐生产**：关闭调试日志/dev 模式等失真项，对比参数完全公平；
     3. **核对错误计数与实际工作量**：验证结果正确且未被死代码消除（DCE）或未 `await` 空跑；
     4. **ABAB 交替 ≥5 轮采样**：取中位数与波动区间（min–max），消除冷启动与系统抖动误判；
     5. **端到端占比校验**：确认该局部热点在真实端到端耗时中的实际占比。
2. **单变量改动与无人值守 `hillclimb` 爬坡循环**：
   - 每轮实验前记录 `git status --porcelain` 未跟踪文件基线，每次只落 **1 个聚焦假设改动**，立刻重跑冻结基准与功能单测，并将数值记入 `decisions.tsv`；
   - **过噪即独立 Commit，未过噪彻底回滚**：若增益低于噪声阈值（或 `<10%` 且明显增复杂度）或功能回归，立即 `git checkout -- .` 并清理本次实验新增的未跟踪文件（严禁污染下一轮 ABAB 采样）；
   - 自动驾驶爬坡持续推进直至命中 `state.json` 的 `predicate`、达到最大轮次，或连续 2 轮无显著收益时自动停损收敛（若发现主瓶颈已迁移，重新评估 Limiter）。
3. **实测汇总**：汇报优化前 vs 优化后真实中位数、波动范围、瓶颈迁移变化、命中 `predicate` 状态及完整复现命令。
