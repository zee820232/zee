# 剧本：性能分析、实证核查与单变量爬坡 (`perf`)

适用场景：启动慢、响应卡顿、包体过大、吞吐瓶颈或无人值守指标持续优化（`hillclimb`）。

## 执行步骤
1. **冻结基准与 7 项实证核查（吸收 `benchmark-checklist`）**：
   - 没有可重复数字前禁止优化；若项目无现成基准，先在 `<busDir>/artifacts/` 建立隔离、可重复执行的基准脚本并登记**成对停止谓词（目标值 + 最小尝试轮次，防撞大运早停）**：
     ```bash
     <ZEE_TOOL> update-state <busDir> --predicate "<客观目标表达式，如 p50<50ms 且至少跑满 5 轮实验、单测全绿>"
     ```
   - 基准脚本须过 7 验：
     1. **Why not double?（明确 Limiter）**：在独立剖析轮次用 profiler / 火焰图 / 耗时分段定位真实主瓶颈（不与计时混跑）；
     2. **配置对齐生产**：关闭调试日志/dev 模式，双边同配调优；若一方无法调优则判 `INCONCLUSIVE` 不硬选胜者；
     3. **物理极限算术核查**：吞吐不得突破磁盘/网络带宽，ops×单次 CPU 不得突破核心数，总加速不得突破 Amdahl 上限（破极限必为假数）；
     4. **错误计数与结果正确性**：统计失败并校验输出正确，防快速报错伪装提速；
     5. **ABAB 交替 ≥5 轮采样**：取中位数与极差（min–max），消除冷启动与系统抖动；
     6. **端到端占比校验**：把微基准折算回真实用户等待路径占比；
     7. **工作真实发生校验**：排除未消费生成器、未 `await` Promise 或 JIT 死代码消除（DCE）导致的空跑。
2. **7 条性能口诀由廉至贵排序 + 单变量 `hillclimb` 循环**：
   - 按性价比由高到低生成假设：① 不做无用功 → ② 缓存不重复做 → ③ 少做数据 → ④ 延迟做 → ⑤ 闲时预做 → ⑥ 并发做 → ⑦ 换更快算法；
   - 每轮实验前记录 `git status --porcelain` 未跟踪文件基线，每次只落 **1 个聚焦假设改动**，立刻重跑冻结基准与功能单测，并将数值记入 `decisions.tsv`；
   - **过噪即独立 Commit，未过噪彻底回滚**：若增益低于噪声阈值或功能回归，立即 `git checkout -- .` 并清理本次实验新增的未跟踪文件；**指标持平但显著简化代码的化简改动予以保留**；
   - 爬坡持续推进直至命中 `predicate`、达最大轮次，或连续 2 轮跨类别假设均无显著收益时停损收敛。
3. **实测汇总**：正文只放 **1 个核心主数字**（优化前→优化后中位数、波动区间、Limiter 与复现命令），详细跑次与剖析产物放 `<busDir>/artifacts/`。
