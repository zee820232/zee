# 剧本：Bug 定位与修复 (`bug-fix`)

适用场景：回归故障、运行报错、构建失败、语法损毁或边界逻辑异常。

## 执行步骤
1. **先抓现象，不靠猜**：收集完整报错栈、失败命令与当前文件真实内容。
2. **红灯先行**：先写或定位最小复现测试，**亲眼看到失败（Red）** 再改实现。
3. **精准读取与快速校验（防破坏现场）**：
   - **同一 `edit` 失败 1 次，必须先 `read` 该行段核对最新内容再重写，禁止带着报错盲目重试**；
   - **每次改完代码立刻跑语法检查（如 `node --check <file>`）和窄单测**，绝不允许残留语法损坏进入下一轮。
4. **最小修补（Green）**：针对根因最小改动，严禁 `@ts-ignore` / `try-catch` 吞错掩盖。
5. **全链路回归与先落袋收口**：复现转绿 + 跑通全量测试与 `.agents/verify-ctl.mjs`，再用 `gate-tamper-diff --working-tree` 收口；**核心成果一经跑绿必须先执行 `update-state`、`log-decision` 与 `git commit` 落袋锁定**，禁止未提交先顺手折腾 Playwright 等外围工具导致超时断尾。
