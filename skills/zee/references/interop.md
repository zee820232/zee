# Skill & Tool Interoperability (`zee` v4.2)

`zee` stays 100% self-contained and never hardcodes third-party skills, packages, or machine-specific paths. It interoperates with host skills and project tools through four strict boundaries.

## 1. Boundary of Three Skill Classes

1. **Domain & Craft Skills** (e.g., frontend craft, framework guides, security checklists, benchmarking):
   - Discovered natively from the active host's `<available_skills>` prompt list.
   - Orchestrator checks `<available_skills>` once during Intake/Design; if a skill clearly matches a unit, pass its exact absolute `location` path to the worker via the Worker Brief (`Optional Reference Skill: <absolute-path>`).
2. **Path-Scoped Project Skills (`pathSkills` — Zero Ambient Context Tax)**:
   - Declare optional `pathSkills` entries in `<repo>/.agents/zee.project.json`:
     ```json
     {
       "pathSkills": [
         { "glob": "src/ui/**", "skill": "verify-app", "roles": ["coder", "ui"] },
         { "glob": "db/migrations/**", "skill": ".agents/skills/db-safety/SKILL.md", "roles": ["coder", "reviewer"] }
       ]
     }
     ```
   - Before spawning a worker slice, resolve matched skills deterministically with:
     `node "<zeeDir>/scripts/zee-tool.mjs" match-skills --repo "<repoRoot>" --files "<csv-of-touched-files>" [--role <role>]`
   - Inject a matched skill ONLY into worker briefs whose touched files match the `glob` (and `roles` if specified), keeping all unrelated sessions free of ambient skill bloat.
3. **Project Commands & Checks**:
   - Declared per repository in `<repo>/.agents/zee.project.json` (`testCmds`, `buildCmd`, `lintCmd`, `uiCheckCmds`, `riskPaths`, `uiGlobs`, `denyCommands`, `trustLevel`, `pathSkills`).
   - `Scout` verifies these commands against repo build manifests; `UI`, `Coder`, and `Verifier` execute them directly rather than hardcoding global tool paths.
4. **Competing Orchestrators / Workflow Controllers**:
   - Never invoked inside `zee` subagents (`[zee-worker]` / `worker.md` + Pi `-ne -e worker-guard.ts` + `ZEE_WORKER=1`).

## 2. Artifact Interop

- All `zee` handoff files (`SPEC.md`, `plan.md`, `DESIGN.md`, `<busDir>/context.md`, `<busDir>/ui-spec.md`, `state.json`, `decisions.tsv`, `.agents/gardening-queue.jsonl`) are standard Markdown, JSON, JSONL, and TSV.
- Approved plans generated by `/zee-plan` (or external planning tools) can be passed directly to `/zee` or `/zee-night` via the Approved Plan Fast-Path without re-interviewing.
